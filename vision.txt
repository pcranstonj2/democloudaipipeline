🚀 Project: Real‑Time Transaction Scoring Pipeline (AI‑Driven Microservice Architecture)
A production‑style system that ingests events, enriches them, calls an AI model, and exposes monitoring + drift detection.

This is exactly what Napier’s AML platform does at scale.

🧩 Architecture Overview
Components you’ll build:
1. Ingestion Service
Accepts incoming “transactions” via REST or Kafka

Validates schema

Publishes to a message queue (Kafka, RabbitMQ, or Azure Event Hub)

2. Feature Enrichment Service
Consumes events

Adds metadata (e.g., geolocation, device info, velocity checks)

Publishes enriched events to another topic

3. Model Serving API
Python FastAPI or Go microservice

Loads a simple model (e.g., scikit‑learn anomaly detector)

Returns a risk score

Exposes /predict endpoint

4. Scoring Orchestrator
Listens for enriched events

Calls the model API

Publishes results to a “scored-transactions” topic

5. Drift Monitor
Tracks feature distributions over time

Compares to training baseline

Logs drift alerts

Exposes metrics via Prometheus

6. Dashboard
Grafana dashboard showing:

throughput

latency

drift metrics

error rates

model confidence

7. Deployment
Docker + Kubernetes

Local cluster (kind/minikube) or Azure Kubernetes Service

Helm charts or Kustomize
